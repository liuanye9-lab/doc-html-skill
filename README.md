# retro-doc-builder

把一场活动、项目或客户交付**复盘成「打法说明书」**的 Agent Skill——产出物是飞书文档，正文承载易变信息，HTML5 Block 承载稳定结构。

> 复盘文档的价值不在「记录发生了什么」，而在**下一个人能不能照着做**。
> 前者是记录，后者是资产。这条区分决定了本 skill 的每一条规则。

## 它解决什么

多数复盘写成了时间顺序的活动记录：先干了 A，再干了 B，效果不错，大家很满意。读完之后，下一个想复用的人依然不知道自己该在哪一步做什么判断。

本 skill 强制三件事：

1. **按决策顺序组织，不按时间顺序** — 为什么做 → 凭什么判断 → 期待什么 → 怎么做 → 效果 → 改什么
2. **必须有劝退清单和失败清单** — 没写「什么情况别做」和「哪些没跑通」的复盘是宣传材料，不是复盘
3. **易变信息留正文，稳定结构进 HTML 块** — 分错了，后续每次更新都要付代价

第二章的**信号 / 前提**二分是整个骨架最锋利的地方：信号差一点可以一起创造条件，前提缺一项就该劝对方先补齐再定时间。合并成「适用条件」就失去指导力。

## 视觉内置 **5 套现代主义极简模板**（苹果式 / 瑞士 / 编辑部 / 画廊 / 技术档案），统一遵守 90% 中性色 + 10% 核心色。

视觉方案经过**五轮否决**才定型，每一轮的结论都是「在减，不在换色」：

| 版本 | 做法 | 反馈 |
|---|---|---|
| v1 | 通用 SaaS 蓝 `#3370FF` + 雷同蓝胶囊 + 渐变 | 不好看 |
| v2 | 暖纸 `#F4F1E8` + 宋体标题 + 发丝线 | 还是不好看 |
| v3 | 白底 + 绿/靛/红三色实底卡 | **颜色太杂** |
| v4 | 白底 + 单色，但仍有 5–6 块实底 | **色块太多** |
| v5 | 白纸 + 线 + 留白，实底仅 1 处 | 方向对了 |
| v7 | 5 套模板 + 间距 ×1.5 + 打破卡片 + 微圆角 0–8px | 当前版本 |
| v6 | 同结构，点缀色换克莱因蓝 `#002FA7` | 当前版本 |

**核心教训：问题从来不是「用哪个颜色」，而是「用了多少块颜色」。** 层级该由字号阶梯、留白、线的粗细承担；每加一块实底，就削弱其余所有实底。

两条硬纪律，检查器会数：

- **实底色块整块 ≤ 1 处**（`.fill` + `.mark` 合计），留给唯一的焦点句
- **只有 1 个彩色色相**，且只作点缀（粗线 / 小标签 / 单个数字），不做彩色实底卡片

### 克莱因蓝为什么要分两档

真 IKB `#002FA7`（RGB 0/47/167）很深。实测对比度：

| | 对白底 | 与近黑 `#111317` 的区分度 |
|---|---|---|
| IKB `#002FA7` | 10.69:1 | **仅 1.74** |
| 亮一档 `#0047D6` | 7.31:1 | 2.54 |

区分度 1.74 意味着**在 11px 小字上会被读成黑色**。所以粗线与实底用真 IKB（面积足够，色相看得出来），小字必须用亮一档。

渲染后用纯标准库解 PNG 采样验证：860×1680 截图里 675 个蓝色像素，400 个落在 IKB 色域——蓝色确实渲染出来了，不是读成黑。

## 三个只有看渲染截图才能发现的坑

静态检查对这三条**全绿**，但成品是坏的：

1. **CSS 特异性静默吃掉颜色** — `.fill p{color:#fff}` 写在 `.bento p{color:...}` 之前会被同特异性覆盖，实底卡上的字变深灰压深底。更隐蔽的是 `.flag`（0,0,1,0）低于 `.bento p`（0,0,1,1），**源码顺序救不了低特异性**，必须写 `.bento p.flag, p.flag, .flag`
2. **`border-top` 粗线配 `border-radius` 会长翘角** — 粗线与细线在圆角处斜接，渲染出突起的小三角。改用 `::before` 画内嵌条 + `overflow:hidden`
3. **Chrome headless 有约 500px 视口下限** — 直接 `--window-size=375` 截图会产出「右边被裁」的**假警报**，据此改 CSS 反而引入真缺陷。窄屏必须用 `<iframe width="375">` 经 HTTP 访问，判据是 `scrollWidth == clientWidth`

## 用法

把 `retro-doc-builder/` 整个目录放进你的 Agent skills 目录，然后说「帮我把这场 workshop 复盘一下」。

自检：

```bash
# 静态：禁用元素 / meta / 色相数 / 实底数 / 字号跨度 / 飞书约束
python3 retro-doc-builder/scripts/check_blocks.py <html目录>

# 渲染：820（飞书正文真实宽度）/ 640 / 360 三档
python3 retro-doc-builder/scripts/render_check.py <html目录> --widths 820,640,360 --out <截图目录>

# 验证两条配色纪律真的在生效
python3 retro-doc-builder/tests/make_negatives.py --check
```

**静态通过 ≠ 好看。** 截图必须实际打开看，确认四件事：字号层级真的拉开了、蓝色在小字上仍是蓝的、发丝线没压过文字、每块有一个明确的视觉重心。

## 依赖

- 写飞书文档需要 `lark-doc`；素材与权限需要 `lark-drive`
- HTML5 Block 写入依赖当前用户的飞书租户权限，**本 skill 不自带任何凭据**
- 渲染自检需本机 Chrome
- 块内零 JS / 零 SVG / 零外链——刻意选择，保证任何环境都能渲染、导出截图不丢内容

## 改这个 skill 之前

两个校验脚本的规则都有回归样本背书（正例 `assets/examples/` + 负例 `tests/`）。**改校验规则必须同时更新样本**，否则规则改动没有证据。

一条自省记录在 `evaluation-record.md` 里：v1 时检查器已报「字号跨度仅 2.1×」，当时用「本块无巨大数字，跨度天然较小」解释过去了——**那是在给缺陷找借口。检查器报的是真问题，用例外解释掉等于关掉检查。**

## v7：5 套模板

同一份 HTML 结构，切换 `<body>` 的主题类即可换风格。

| 模板 | 版面原型 | 自己的架构组件 | 核心色 |
|---|---|---|---|
| `t-modern` | 产品页 tile 序列 | `.tile` `.statrow` `.feats` `.pills` | 克莱因蓝 `#002FA7` |
| `t-swiss` | 海报式 12 栏网格 | `.poster` `.gwall` `.sbar` `.hang` | 瑞士红 `#E30613` |
| `t-editorial` | 报纸头版 | `.mast` `.lede` `.flow` `.pullq` `.withbar` | 无（纯黑白灰） |
| `t-gallery` | 展览动线 | `.walk` `.plate` `.vitrine` | 石墨青 `#4E6E7A` |
| `t-mono` | 终端记录卡 | `.rec` `.kv` `.readout` `.entries` | 深靛 `#26346B` |

**硬规则**：每套模板必须用自己的一组架构组件（<3 个报 ERROR），且不得借用别套的组件。
五套模板是**五种版面架构**——报头形态、阅读顺序、信息容器都不同，不是同一份骨架换配色。

### 五套共同遵守的基调

| # | 基调 | 可检查的判据 |
|---|---|---|
| 1 | 克制的色彩 | 90% 中性 + 10% 核心色；色相 >1 → ERROR；核心色占比 >18% → WARN |
| 2 | 极致留白 | 间距是常规值的 1.5 倍（6/12/18/24/36/48/72）；`--band` ≥72px |
| 3 | 打破卡片 | 分隔只用通栏模块、细横线、纯留白三种 |
| 4 | 微圆角无阴影 | 圆角 0–8px；阴影 alpha ≤.06 且 blur ≥48px，整块最多一处 |
| 5 | 现代无衬线 | 标题粗 600–700、正文细 400 |

### 实测结果

- 五套正例静态检查 **5/5 PASS，ERROR 0 / WARN 0**
- 核心色占比五套均 **13%**（9/68 个元素），符合 90/10
- 字号跨度 **8.7×**（11–96px）
- 375px 窄屏五套全部 `fits=true overflow=0`
- 负例 **10/10 全部被拦住**（含 `shared-skeleton`：换主题类但骨架照抄别套）

### 用法

```bash
python3 scripts/make_themes.py --check      # 生成 5 套并静态检查
python3 tests/make_negatives.py --check     # 8 条负例必须全被拦住
```
