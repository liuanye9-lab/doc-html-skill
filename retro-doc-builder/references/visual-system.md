# v7 视觉系统｜5 套模板 · 90% 中性 + 10% 核心色

写任何 HTML5 Block 之前必须读完本文件。唯一权威 token 源是 `../assets/base.css`。

## 基础视觉基调（五套模板共同遵守，不可协商）

整体严格遵循**苹果官网式的现代主义极简**：克制、高级、有呼吸感。

| # | 基调 | 落地方式 | 检查器 |
|---|---|---|---|
| 1 | **克制的色彩** | 90% 中性色（黑白灰）+ 10% 单一核心色。色彩为内容服务，不用于吸引注意 | 色相 >1 → ERROR；核心色占比 >18% → WARN |
| 2 | **极致留白** | 间距比常规大 **1.5 倍**；宁可空着也不填满 | `--s1..s7` 必须是 6/12/18/24/36/48/72；`--band` ≥72px |
| 3 | **打破卡片** | 不用带阴影的封闭卡片。分隔只用三种：通栏模块、细横线、纯留白 | ≥3 处「1px 边框 + 内边距」→ WARN |
| 4 | **微圆角 + 无阴影** | 圆角 0–8px；阴影要么没有，要么极淡（alpha ≤.06）且范围极大（blur ≥48px），整块最多一处 | 圆角 >8px → ERROR；阴影过重或过小 → ERROR |
| 5 | **现代无衬线** | 标题粗（600–700）、正文细（400）。正文加粗只到 600 | — |

**拒绝**：廉价渐变、高饱和色、密集色块、格子卡片感、带阴影的封闭卡片。

## 三种分隔手段（按优先级）

这是「打破卡片」的具体做法。**先想能不能用留白，其次细横线，最后才是通栏换底色。**

1. **纯留白** —— 不需要任何元素。`--band` 88px 起，画廊主题 120px
2. **细横线** —— `.rule` / 顶线 `.u-t` `.u-h` `.u-k` / `.stack` 的行线
3. **通栏模块** —— `.band.alt` 换浅底、`.band.ink` 换深底。**底色变化本身就是分隔线，不要再加边框**

## 五套模板

切主题只改 body 的 class，HTML 结构完全不动。

| class | 名称 | 参考风格判据 | 核心色 | 圆角 | `--band` |
|---|---|---|---|---|---|
| `t-modern` | 苹果式现代主义 | 通栏交替、底色变化即分隔、正文 17px、字重跳过 500 | 克莱因蓝 `#002FA7` | 6px | 88px |
| `t-swiss` | 瑞士国际主义 | 直角、一律左对齐、右侧留白有构成作用、三档灰建层级 | 瑞士红 `#E30613` | 0 | 80px |
| `t-editorial` | 杂志编辑部 | 字号对比拉到 10:1、细横线、区块间 100px+ 留白 | 无（纯黑白灰） | 0 | 104px |
| `t-gallery` | 画廊极简 | 留白最大化、字号收小、点缀近中性 | 石墨青 `#4E6E7A` | 2px | 120px |
| `t-mono` | 技术档案 | 等宽字面、表格化数据、口径清单 | 深靛 `#26346B` | 0 | 80px |

**怎么选**：
- 默认、对外分享、要「高级感」→ `t-modern`
- 数据密集、要秩序感与权威 → `t-swiss`
- 叙事型复盘、有原声与长文 → `t-editorial`
- 内容少但要显得郑重 → `t-gallery`
- 口径、清单、对照表为主 → `t-mono`

**同一份文档的所有块必须用同一套主题。** 混用等于没有视觉系统。

## 配色纪律（最先读这两条）

> **1 实底色块整块最多 1 处**，留给唯一的焦点句。
> **2 彩色只作点缀**——细线、小标签、单个关键数字。**不做彩色实底卡片。**

七轮演进，每一轮都是在减：

| 版本 | 做法 | 用户反馈 |
|---|---|---|
| v1 | 通用 SaaS 蓝 + 14 个雷同蓝胶囊 + 渐变 | 风格实在不好看 |
| v2 | 暖纸 + 宋体 + 发丝线 | 还是不好看 |
| v3 | 白底 + 绿/靛/红三色实底卡 | **颜色太杂** |
| v4 | 白底 + 单个红，但仍有 5–6 块实底 | **色块太多** |
| v5 | 白纸 + 线 + 留白，实底仅 1 处 | 色系方向对了 |
| v6 | 同结构，点缀色换克莱因蓝 | 认可 |
| v7 | 5 套模板 + 间距 ×1.5 + 打破卡片 + 微圆角 | 当前版本 |

**核心教训：问题从来不是「用哪个颜色」，而是「用了多少块颜色」。** 层级该由字号阶梯、留白、线的粗细承担；每加一块实底，就削弱其余所有实底。

## 核心色必须分两档（实测结论）

以克莱因蓝为例。真 IKB `#002FA7` 很深，实测对比度：

| | 对白底 | 与 ink `#1D1D1F` 的区分度 |
|---|---|---|
| IKB `#002FA7` | 10.69:1 | **仅 1.74** |
| 亮一档 `#0047D6` | 7.31:1 | 2.54 |

**区分度 1.74 意味着在小字号上会被读成黑色**——和早前那个深绿 `#2C5545`（区分度 2.04，渲染出的像素只有正常值的 1/11）踩的是同一个坑。

所以分两档：`--key` 用于 2–3px 粗线与实底（面积够，色相看得出来）；`--key-lt` 专供 11–13px 小字。渲染后已用像素采样验证蓝色确实渲染出来了，不是读成黑。

## 单元四档（全部无边框、无阴影）

不靠填色区分轻重，靠**顶线的有无、粗细、颜色**：

| 档 | class | 视觉 | 用途 |
|---|---|---|---|
| 裸 | `.u` | 只有留白 | 最轻，靠间距成组 |
| 常规 | `.u-t` | 顶部 1px 细线 | 主体内容 |
| 结构必备 | `.u-h` | 顶部 2px 近黑线（`.c4` 时 3px） | 硬门槛、总闸 |
| 警示 | `.u-k` | 顶部 2px 核心色线 | 劝退、致命项。**彩色只在这条线上** |
| 安静 | `.u-q` | 极浅底 + 微圆角，无边框 | 需要成组但不抢视线 |
| 焦点 | `.mark` | 近黑实底 + 白字 | **整块唯一一处** |

## 字号阶梯

| 用途 | 字号 | 字重 |
|---|---|---|
| 报头序号 `.hero .no` | 72px（编辑部 96px） | 700 |
| 巨数 `.fig` | 52px（编辑部 64px） | 700 |
| 报头标题 `.hero h1` | 36px | 700 |
| 焦点带 `.mark .big` | 26px | 600 |
| 引语 `.quote` | 21px | 500 |
| 引导语 `.hero .dek` | 17px | 400 |
| 卡内标题 `.ct` | 17px | 600 |
| 正文 | 15px | 400 |
| 标签 `.lb` | 11px | 600 + 字距 |

实测跨度 **8.7×**（11–96px）。跨度低于 2.0× 检查器会警告。

## 四个必须记住的实现坑（都是踩出来的，静态检查全绿）

1. **反白文字被覆盖**：`.fill p{color:#fff}` 若写在 `.grid p{color:var(--ink-2)}` **之前**，会被同特异性的后者盖掉，实底上的字变深灰几乎读不到。base.css 已排好顺序，**不要调整这两段先后**。

2. **低特异性救不了**：`.flag`（0,0,1,0）低于 `.grid p`（0,0,1,1），**源码顺序无效**——必须写成 `.grid p.flag, p.flag, .flag{...}`。

3. **粗线配圆角出翘角**：`border-top:3px` 配 `border-radius` 会在上角产生斜接翘角。v7 的顶线画在无圆角的单元上，规避了这个问题；若要给带圆角的元素加顶线，用 `::before` 内嵌条 + `overflow:hidden`。

4. **实心刻度条像涂黑**：4px 高的实心分段条渲染出来像「删改条」，很脏。改成 1px 发丝线才读作「计数刻度」而不是「一块颜色」。

## 节奏配方

一个块内推荐顺序（**不要连续两个同类**）：

```
.band          报头（巨型序号 + 三段式，左对齐）
.band          开放网格（1 个跨列主单元 + 2–3 个小单元，尺寸拉开）
.band.alt      竖排条目（换底色 = 换段落，与网格形成密度反差）
.band          .mark 焦点带（全块唯一一次）+ 主次混合网格
.band.alt      次要网格（用 .u-t 轻档）
.band          表格 / .foot 收口
```

## 自检

```bash
python3 scripts/make_themes.py --check       # 生成 5 套并静态检查
python3 tests/make_negatives.py --check      # 8 条负例必须全部被拦住
python3 scripts/render_check.py <目录> --widths 820,640,360 --out <截图目录>
```

**静态通过 ≠ 好看。必须实际看渲染截图**，确认：实底上的字是白的、每个网格有明显主次单元、相邻区块不同高、核心色真的看得出色相。

窄屏必须用 `<iframe width="375">` 经 HTTP 访问测量，**不要用 `--window-size=375` 截图**——Chrome headless 有约 500px 视口下限，会产出「右边被裁」的假警报。判据是 `scrollWidth == clientWidth` 且无元素 `right` 越界。v7 五套主题实测 375px 全部 `fits=true overflow=0`。
