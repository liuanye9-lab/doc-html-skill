# v6 视觉系统｜黑白灰 + 克莱因蓝点缀

写任何 HTML5 Block 之前必须读完本文件。唯一权威 token 源是 `../assets/base.css`。

## 这一版要解决的问题

前两版（通用 SaaS 蓝 → 暖纸档案风）都被判「不好看」。**第二版的失败原因不是配色，是结构**：每个小节都是标题 + 等分栏，通篇同一种密度，所以没有任何东西「跳出来」。

两条来自公开设计实践的判据直接命中这个毛病：

> **「全等分格子就不是 bento」**——如果每个单元大小相同，你只是给普通卡片墙换了个时髦名字，白付了复杂度成本。**只有当尺寸编码优先级时，这个结构才值得用。**（superdesign bento-grid）

> **「同高卡片墙」= 坏节奏。绝不要把两个同高区块上下相邻。**（styleseed 视觉节奏指南）

所以核心不是换色，是**让尺寸承担层级**。

## 四条不可违背的原则

| # | 原则 | 具体做法 |
|---|---|---|
| 1 | **尺寸编码优先级** | 每个 `.bento` 至少有一个跨列更大的主单元。全 `c2` 等分会被检查器警告 |
| 2 | **相邻区块不得同高** | bento 网格 ↔ 竖排 `.stack` ↔ 深底 `.mark` 交替出现 |
| 3 | **字号金字塔** | 序号 64px → 巨数 44px → 报头 32px → 卡内标题 16px → 正文 13.5px → 标签 11px |
| 4 | **少用色块** | 实底合计 ≤1 处，彩色点缀 ≤6 处。层级交给字号、留白、顶线粗细 |

## 配色纪律（最先读这两条）

> **1 实底色块整块最多 1 处**，留给唯一的焦点句。
> **2 彩色只作点缀**——细线、小标签、单个关键数字。**不做彩色实底卡片。**

四轮否决的演进，每一轮都是在减：

| 版本 | 做法 | 用户反馈 |
|---|---|---|
| v2 | 暖纸 + 宋体 + 发丝线 | 不好看 |
| v3 | 白底 + 绿/靛/红三色实底卡 | **颜色太杂** |
| v4 | 白底 + 单个红，但仍有 5–6 块实底 | **色块太多** |
| v5 | 白纸 + 线 + 留白，实底仅 1 处，红色点缀 | 色系方向对了 |
| v6 | 同结构，点缀色换克莱因蓝 | 当前版本 |

**核心教训：问题从来不是"用哪个颜色"，而是"用了多少块颜色"。** 层级该由字号阶梯、留白、线的粗细承担；每加一块实底，就削弱其余所有实底。

全部用色（1 个彩色色相）：

```
底面   --page   #FFFFFF   纯白，卡片也是白的
       --cell   #FAFAFB   几乎不可见的浅灰，只用于安静分组
       --cell-2 #EDEEF1   进度条槽底
墨     --ink    #111317   近黑    --ink-2 #4A5058 正文   --ink-3 #8A9099 元信息
线     --line   #E4E6EA   卡片描边与分隔   --line-2 #C9CDD4 巨型序号
点缀   --accent    #002FA7  克莱因蓝 IKB（真色值，RGB 0/47/167）
                            用于 3px 粗线与实底——面积够大，色相看得出来
       --accent-lt #0047D6  同色亮一档，专用于 11–13px 小字
                            必须分两档，理由见下
圆角   --r 14px
间距   4 / 8 / 12 / 16 / 24 / 32 / 48
```

**检查器会数**：实底块（`.fill` + `.mark`）超过 1 处直接 ERROR；彩色点缀超过 6 处警告。

## 克莱因蓝必须分两档（实测结论）

真 IKB `#002FA7` 很深。实测对比度：

| | 对白底 | 与 ink `#111317` 的区分度 |
|---|---|---|
| IKB `#002FA7` | 10.69:1 | **仅 1.74** |
| 亮一档 `#0047D6` | 7.31:1 | 2.54 |

**区分度 1.74 意味着在小字号上会被读成黑色**——这和早前那个深绿 `#2C5545`（区分度 2.04，渲染出的像素只有正常值的 1/11）踩的是同一个坑。

所以分两档，各有明确用途：

- **`--accent` 真 IKB**：3px 粗线、实底、大面积。面积足够时色相看得出来，深一点反而更接近克莱因蓝本身的浓度
- **`--accent-lt`**：11–13px 的 kicker、小节标签、行内 `.flag`。**小字必须用这一档**，否则蓝色白给

渲染后已用像素采样验证：860×1680 的截图里采到 675 个蓝色像素，其中 400 个落在 IKB 色域——**蓝色确实渲染出来了，不是读成黑**。

## 卡面四档（全部白底，只有线不同）

不靠填色区分轻重，靠**顶线的有无、粗细、颜色**：

| 档 | class | 视觉 | 用途 |
|---|---|---|---|
| 结构必备 | `.cell-hd` | 白底 + 顶部 3px 近黑条 | 硬门槛、总闸 |
| 警示 | `.cell-acc` | 白底 + 顶部 3px 克莱因蓝条 | 劝退、致命项。**彩色只在这条线上** |
| 常规 | `.cell` | 白底 + 1px 描边 | 主体内容 |
| 安静 | `.cell-q` | 极浅灰底 + 1px 描边 | 需要成组但不抢视线的条目 |
| 焦点 | `.mark` | 近黑实底 + 白字 | **整块唯一一处**（也是全块唯一实底），留给最该记住的一句 |

### 顶线必须用 `::before`，不能用 `border-top`

`border-top:3px` 配 `border-radius` 会在两个上角产生**斜接「翘角」**——粗线与细线在圆角处交汇，渲染出一个突起的小三角，很难看。

base.css 已改用 `::before` 画内嵌条 + `overflow:hidden`。**这个只有看渲染截图才会发现，静态检查全绿。**

## 反白文字的坑（实际踩过）

`.fill p{color:#fff}` 若写在 `.bento p{color:var(--ink-2)}` **之前**，会被同特异性的后者覆盖，实底卡上的文字变成深灰压在深底上——几乎读不到。

**base.css 已把 `.fill` 的文字覆盖放在通用段落规则之后**，不要调整这两段的先后顺序。

**同类的第二个坑**：`.flag`（0,0,1,0）特异性低于 `.bento p`（0,0,1,1），**源码顺序救不了低特异性**——必须写成 `.bento p.flag, p.flag, .flag{...}` 才生效。第一次改单色时就因为这个，红色行内标记静默变回灰色。

改 CSS 后必须重新截图确认：实底卡上的字是白的、`.flag` 是红的。

## 字号阶梯

| 用途 | 字号 | 字重 |
|---|---|---|
| 报头序号 `.hero .no` | 64px | 800（浅灰，不是实底）|
| 巨数 `.fig` | 44px | 800 |
| 报头标题 `.hero h1` | 32px | 700 |
| 焦点带 `.mark .big` | 23px | 700 |
| 竖排序号 `.stack .n` | 20px | 800 |
| 引语 `.quote` | 19px | 600 |
| 卡内标题 `.ct` | 16px | 700 |
| 正文 | 13.5px | 400 |
| 卡标签 `.lb` | 11.5px | 700 + 字距 |

实测跨度 **5.8×**（11–64px）。层级不足是前两版最大的问题，跨度低于 2.5× 检查器会警告。

## 禁令

| 禁 | 替代 |
|---|---|
| 米黄 / 暖纸底色 | 纯白 `--page` |
| 通用 SaaS 蓝 `#3370FF` | 克莱因蓝 `--accent`（两者不是一回事，检查器分得清）|
| 任何渐变 | 纯色实底 |
| `box-shadow` | 靠发丝线、留白、顶线粗细建立层次 |
| 小圆角（1–9px） | 14px 圆角 `--r` |
| 全等分卡片网格 | 尺寸编码优先级 |
| **用第二个颜色编码语义** | 用顶线粗细档（`.cell-hd` / `.cell-acc` / `.cell` / `.cell-q`）|
| **多个实底色块堆在一起** | 实底只留 1 处；其余改白底 + 顶线 |
| `border-top` 粗线配圆角 | 用 `::before` 内嵌条，避免斜接翘角 |
| emoji / ✓ × ! 当图标 | 文字标签或 CSS 画 |
| 亮绿 `#00B42A` / 亮橙 `#FF7D00` / 任何第二色相 | 一律不用；只有克莱因蓝一个色相（两个明度档）|
| 外链字体图片图表库 · `<script>` · `<svg>` | 系统字体 + CSS 造形 |
| 中文写 `font-style:italic` | 中文字体无真斜体，会合成倾斜；用字重与字号 |

## 节奏配方

一个块内推荐顺序（不要连续两个同类）：

```
.hero 报头（白底 + 顶部粗线 + 巨型浅灰序号）
.bento 摘要网格（1 个大主单元 + 2–3 个小单元，尺寸拉开）
.sec 小节标签
.stack 竖排条目（与网格形成密度反差）
.mark 焦点带（全块唯一一次）
.sec + .bento 主次混合网格
.sec + .bento 次要网格（用 .cell-q 安静档）
表格 / .foot 收口
```

## 自检

```bash
python3 ../scripts/check_blocks.py <目录>    # 禁用元素 / meta / token / 等分网格 / 字号跨度
python3 ../scripts/render_check.py <目录>    # 溢出 / 塌陷 / 语义色像素
```

**静态通过 ≠ 好看。必须实际看渲染截图**，尤其确认：实底卡上的字是白的、每个网格有明显的主次单元、相邻区块不同高。

窄屏必须用 `<iframe width="375">` 经 HTTP 访问测量，**不要用 `--window-size=375` 截图**——Chrome headless 有约 500px 视口下限，会产出「右边被裁」的假警报。判据是 `scrollWidth == clientWidth` 且无元素 `right` 越界。
